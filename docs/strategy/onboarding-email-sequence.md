## STRATÉGIE OMNICANALE — RETARGETING & HIGH-TOUCH

### Retargeting Publicitaire (Meta / LinkedIn)

**Audience cible :** Utilisateurs inscrits en cours d'essai gratuit (J0 à J14)

**Contenu des créatives :**
1. Étude de cas : "Comment [Agence X] a gagné 12h/semaine avec Kompilot"
2. Preuve sociale : Capture d'écran dashboard avec données floutées + "Votre rapport vous attend"
3. Gains de temps : Infographie comparative "Avant / Après Kompilot"

**Approche :** Pas de survendre l'outil. Renforcer l'usage et la valeur perçue pendant l'essai. Objectif : réduire le churn à J14.

### Stratégie High-Touch (Alerte Leads Qualifiés)

**Trigger automatique :** Dès qu'un email avec domaine "agence", "digital", "marketing", "communication" ou entreprise vérifiée s'inscrit.

**Workflow :**
1. Webhook Slack/Discord vers canal `#high-touch-leads` avec : nom, email, entreprise, secteur
2. Alert Romain (Sales) sous 4 heures maximum
3. Message LinkedIn personnalisé : "Bonjour {{prénom}}, j'ai vu votre inscription sur Kompilot — je serais curieux de votre feedback. Un café virtuel de 15 min cette semaine ?"
4. Lien Calendly inclus
5. Si pas de réponse sous 48h : email de suivi + séquence LinkedIn

## IMPLÉMENTATION TECHNIQUE

### Table `magic_link_tokens` (déjà existante)

```sql
CREATE TABLE IF NOT EXISTS magic_link_tokens (
  id TEXT PRIMARY KEY,
  email TEXT NOT NULL,
  token_hash TEXT NOT NULL,
  lookup_hash TEXT NOT NULL,
  redirect_url TEXT,
  expires_at TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

### Webhook Stripe `invoice.payment_failed`

Route backend existante : `backend/routes/webhooks.ts` — vérifier que le handler envoie l'email de dunning.

### Segmentation email

Utiliser la table `users` + `onboarding_profiles` + logs d'activité pour segmenter :
- `has_connected_account` : a connecté au moins un compte
- `has_completed_scan` : a lancé au moins un scan
- `days_since_signup` : nombre de jours depuis l'inscription
- `plan_status` : trial / active / paused / churned
